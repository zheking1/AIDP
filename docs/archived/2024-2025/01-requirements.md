# AI 编程基础设施平台需求说明

## 1. 项目背景

当前 AI 编程主要问题：

1. AI 不熟悉项目私有业务文档、接口规范、数据库结构和历史决策。
2. 技术文档、项目文档、历史排坑经验分散，无法被 Agent 自动检索。
3. AI 生成代码缺乏实时编译、运行、测试反馈，容易停留在文本层面。
4. 长会话容易上下文溢出，重复传入规范和项目背景造成 token 浪费。
5. 代码片段、模板、历史方案无法体系化沉淀和复用。
6. 质量校验依赖人工，无法形成生成、验证、修复闭环。

本项目建设一套私有化 AI 编程基础设施平台。平台由 `aidp-controller` 主服务和 N 个可选安装工具组成，为 MCP Agent 提供知识检索、代码资产检索、沙箱执行、上下文记忆、质量校验等基础能力。

## 2. 产品目标

### 2.1 总目标

构建一个支持私有化部署的 AI 研发操作平台，使 AI Agent 能够基于项目真实知识生成、验证、修复、沉淀代码。

### 2.2 阶段目标

MVP 阶段：

- 支持文档上传、解析、向量化和检索。
- 支持工具可选安装、启用、停用。
- 支持 MCP Agent 通过 Tool Capability 调用已安装工具。
- 支持代码片段和项目模板管理。
- 支持基础代码执行与项目编译验证。
- 支持质量检查结果结构化返回。

增强阶段：

- 支持长期记忆、会话压缩和多项目上下文隔离。
- 支持报错知识库自动沉淀。
- 支持 Node/TypeScript、Python、Flutter 等构建和测试镜像。
- 支持项目结构自动分析。
- 支持评测集和 Prompt/Skill 回归测试。

## 3. 用户角色

| 角色 | 说明 | 核心操作 |
|---|---|---|
| 平台管理员 | 维护系统、租户、权限、服务配置 | 配置用户、项目、工具、Skill、系统参数 |
| 项目负责人 | 管理项目文档、代码模板、规范 | 创建项目空间、上传文档、维护规则 |
| 开发者 | 使用 AI 生成、修改、验证代码 | 发起开发任务、查看执行结果 |
| AI Agent | 通过 MCP 调用平台能力 | 检索知识、获取模板、执行代码、提交校验 |
| 审计人员 | 查看调用链、来源、操作记录 | 查询日志、追踪文档引用和代码变更 |

## 4. 核心业务场景

### 4.1 基于项目文档生成代码

用户提出需求：“根据 ERP 销售订单规则新增审批接口”。

系统流程：

1. aidp-controller 识别任务所属项目和会话。
2. 调用 knowledge-tool 检索销售订单、审批流、接口规范、数据库表结构。
3. 调用 asset-tool 检索相似接口实现和通用模板。
4. AI 生成代码。
5. 调用 sandbox-tool 编译项目。
6. 调用 quality-tool 检查接口格式、命名规范、SQL 风险。
7. 若失败，返回错误给 AI 自动修正。

验收标准：

- 检索结果必须带来源、版本、更新时间。
- 编译失败日志可结构化返回。
- 最终输出包含改动摘要、验证结果和引用文档列表。

### 4.2 历史报错自动复用

用户粘贴构建错误或运行异常。

系统流程：

1. aidp-controller 调用 error-tool 检索相似错误。
2. 返回历史解决方案、关联提交、适用版本。
3. AI 根据当前项目差异给出修复方案。
4. 沙箱执行验证。

验收标准：

- 相似错误返回相似度分数。
- 历史方案必须标注适用技术栈和版本。
- AI 不能无来源地断言历史结论。

### 4.3 项目模板初始化

用户要求创建新项目或新模块。

系统流程：

1. aidp-controller 调用 template-tool 检索合适脚手架。
2. 下载模板包。
3. 替换项目变量。
4. 执行初始化命令。
5. 编译验证。

验收标准：

- 模板有版本、标签、适用范围。
- 初始化参数可配置。
- 初始化结果可重复执行。

## 5. 功能需求

### 5.1 文档知识库

必须支持：

- 文档分类：通用技术文档、项目私有文档、历史方案、报错知识。
- 文件类型：Markdown、PDF、Word、HTML、TXT。
- 文档上传到本地文件存储；MinIO 作为团队部署可选项。
- 文档元数据入 PostgreSQL。
- 文档解析、切片、向量化。
- 按租户、项目、空间、标签、版本过滤检索。
- 检索结果返回来源、片段、相似度、更新时间。
- 文档重新索引和删除索引。

建议支持：

- 网页抓取入库。
- Git 仓库 Markdown 自动同步。
- 文档过期提醒。

### 5.2 代码资产库

必须支持：

- 代码片段管理。
- 项目模板管理。
- 历史解决方案管理。
- 标签、语言、框架、项目类型过滤。
- 自然语言检索代码片段。
- 模板压缩包存储到本地文件存储；MinIO 作为团队部署可选项。

建议支持：

- 从 Git 提交中提取代码方案。
- 代码片段自动生成说明和标签。

### 5.3 执行与编译沙箱

必须支持：

- Shell、Python、SQL 轻量执行。
- Node/TypeScript 项目构建与测试。
- 执行超时控制。
- CPU、内存、磁盘限制。
- 网络隔离策略。
- 执行日志采集。
- 结构化返回退出码、标准输出、标准错误、产物路径。

建议支持：

- Python 测试镜像。
- Flutter 构建镜像。
- 临时数据库实例。

### 5.4 上下文与记忆管理

必须支持：

- 项目级长期记忆。
- 会话级短期上下文。
- 会话摘要。
- 记忆按项目隔离。
- MCP 按 session_id 获取上下文包。

建议支持：

- 自动压缩历史对话。
- 重要决策提取。
- 记忆过期与人工审核。

### 5.5 quality-tool

必须支持：

- 按项目类型加载规则集。
- 调用格式化、Lint、单元测试、编译检查。
- 返回结构化问题列表。
- 标注错误级别、文件、行号、建议修复方式。
- 校验失败可作为 AI 下一轮修复输入。

建议支持：

- SQL 慢查询风险检查。
- 自定义编码规约。
- 安全扫描。

### 5.6 工具安装与 MCP Skill 映射

必须支持：

- 工具通过 `tool.yaml` 声明能力、依赖、接口和配置项。
- aidp-controller 支持安装、启用、停用工具。
- Tool Capability 自动映射为 MCP Skill。
- Capability 输入输出 Schema 管理。
- 工具调用日志。
- 工具调用链 trace_id。
- 工具调用超时、重试、熔断。

## 6. 非功能需求

### 6.1 安全

- 全部服务私有化部署。
- 项目级权限隔离。
- 沙箱默认禁止访问内网敏感地址。
- 文档检索必须按权限过滤。
- 所有外部调用必须记录审计日志。

### 6.2 性能

MVP 指标：

- 文档检索 P95 小于 1500ms。
- 代码片段检索 P95 小于 1000ms。
- 小脚本执行启动小于 3s。
- Node/TypeScript 构建测试按项目大小设定上限。

### 6.3 可观测性

- 所有 MCP 调用带 trace_id。
- 记录工具输入摘要和输出摘要。
- 记录文档引用来源。
- 记录沙箱资源使用情况。
- 记录 quality-tool 失败原因。

### 6.4 可扩展性

- 新增工具或 capability 不需要改 controller 核心代码。
- 新增文档类型通过解析器插件扩展。
- 新增校验规则通过规则配置扩展。
- 新增构建环境通过镜像模板扩展。

## 7. 验收总标准

平台 MVP 完成时，必须能演示以下端到端流程：

1. 上传一份项目接口规范和数据库说明。
2. 文档自动切片并入向量库。
3. 通过 MCP Skill 按自然语言检索到相关片段。
4. 上传一段 TypeScript 代码片段并通过自然语言检索。
5. AI 根据检索结果生成一个简单 TypeScript/Fastify 接口。
6. 沙箱执行 Node/TypeScript 测试。
7. quality-tool 返回编译和 Lint 结果。
8. 失败时 AI 能根据错误日志修复一次。
